## 1. 요약

| 항목 | 결정 |
|---|---|
| 영상 모델 | **YOLO26n-pose** (Ultralytics) — 아기 검출 + 관절 위치(키포인트) 추정 |

## 2. 왜 YOLO인가

### 2-1. 맘캠이 모델에 요구하는 조건

PRD와 전처리 설계에서 정한 조건은 다음과 같다.

1. **기기 안에서 실시간 실행:** 저전력 NPU, 모델 용량 약 15MB, 초당 5프레임 분석
2. **영상이 밖으로 나가지 않음:** 클라우드 추론을 쓸 수 없다
3. **자세를 구분할 수 있어야 함:** 단순히 "아기가 있다"가 아니라 머리·어깨 방향까지 알아야 한다
4. **밤 IR 영상에서도 동작:** 흑백, 노이즈, 저대비 환경

### 2-2. 후보 비교

| 후보 | 장점 | 한계 | 판단 |
|---|---|---|---|
| **YOLO26n-pose** | 검출과 키포인트를 한 번에 추정, 파라미터 2.9M으로 매우 작음, 엣지용 설계(NMS 없는 추론 지원) | 성인 데이터(COCO)로 학습돼 있어 아기에 맞게 다시 학습 필요 | **주 모델로 채택** |
| YOLO26n-cls | 구조가 가장 단순, 이미지를 바로 자세 클래스로 분류 | 왜 그렇게 판단했는지(머리 위치 등) 설명하기 어려움 | **비교 실험용** |
| 2단계 방식 (검출기 + 별도 자세 모델) | 정확도를 높이기 쉬움 | 모델이 두 개라 연산·용량이 늘어남 | 제외 |
| 큰 자세 모델 (예: 고해상도 자세 추정 전용 모델) | 키포인트 정확도 높음 | 저전력 NPU에서 5fps를 맞추기 어려움 | 제외 |

### 2-3. YOLO26을 고른 이유

Ultralytics 문서에 따르면 YOLO26은 2026년 1월에 공개됐고, 엣지 기기를 목표로 다음과 같이 설계됐다.

- **NMS 없는 추론 옵션:** 후처리 단계(NMS)를 생략할 수 있어 NPU 변환과 실행이 단순해진다.
- **DFL 제거:** 검출 헤드가 단순해져 내보내기(export)가 쉬워진다.
- **CPU 추론 속도:** 논문 기준 YOLO11n보다 CPU(ONNX)에서 최대 43% 빠르다고 보고됐다.
- **pose(자세) 작업 지원:** n, s, m, l, x 다섯 크기 모두에서 지원한다.

COCO 데이터셋 기준 pose 모델 비교 (Ultralytics 공식 문서 수치, 640px 입력):

| 모델 | 파라미터 | 연산량 | mAP-pose 50-95 | CPU ONNX 속도 |
|---|---:|---:|---:|---:|
| **YOLO26n-pose** | **2.9M** | **7.6B** | **57.2** | **40.3ms** |
| YOLO26s-pose | 10.4M | 24.1B | 63.0 | 85.3ms |
| YOLO26m-pose | 21.5M | 73.3B | 68.8 | 218.0ms |

**n(nano) 크기를 고른 근거**

- **용량:** 2.9M 파라미터는 INT8 양자화 시 약 3MB로, 15MB 예산 안에 오디오 모델까지 함께 들어간다.
- **속도:** 맘캠은 640px이 아니라 **256×192**로 줄여 넣으므로 연산량이 640px 대비 약 1/8로 줄어든다. 5fps(프레임당 200ms) 안에 처리할 여유가 있다.
- **정확도:** 맘캠은 화면에 아기 한 명만, 크게 나온다(ROI 크롭 덕분). 여러 사람이 작게 나오는 COCO보다 쉬운 문제라 작은 모델로도 충분할 것으로 예상한다. 단, 이는 가정이므로 6장의 실험으로 확인한다.

### 2-4. 오디오(울음)에는 YOLO를 쓰지 않는 이유

YOLO는 이미지 속 물체의 **위치**를 찾는 모델이다. 울음 감지는 "이 1초 동안 울음이 있었나"를 판단하는 **분류** 문제라서 위치 정보가 필요 없다. 멜 스펙트로그램을 이미지처럼 YOLO-cls에 넣을 수도 있지만, 오디오 전용 경량 CNN(입력 96×64)이 더 작고 빠르다. 따라서 울음 감지는 별도 오디오 CNN으로 설계한다.

## 3. 전체 구조

```
[카메라 1080p 15fps]
   └→ 전처리 (report/preprocessing.md 1~10단계)
        └→ 256×192 흑백 이미지
             └→ YOLO26n-pose  →  아기 위치 + 키포인트 7개 + 각 신뢰도
                  └→ 자세 특징 계산 (머리-어깨 방향, 얼굴 점 보임 여부 등)
                       └→ 자세 분류기(MLP)  →  바로 / 옆 / 엎드림 / 확인 필요 확률
                            └→ 5초 지속 판정  →  기기 경보 + 보호자 알림

[마이크 16kHz]
   └→ 전처리 → 로그 멜 96×64 → 오디오 CNN → 울음 확률 → 10초 지속 판정 → 알림
```

### 3-1. 아기용 키포인트 7개

COCO의 사람 키포인트 17개 중, 속싸개를 한 아기에게서도 보이는 점과 자세 구분에 필요한 점만 남긴다.

| 번호 | 키포인트 | 쓰는 이유 |
|---|---|---|
| 0 | 코 | 얼굴이 위를 보는지 판단하는 핵심 점. 엎드리면 보이지 않는다 |
| 1, 2 | 왼눈, 오른눈 | 얼굴 방향, 좌우 판별 |
| 3, 4 | 왼귀, 오른귀 | 옆으로 누웠을 때 한쪽만 보인다 |
| 5, 6 | 왼어깨, 오른어깨 | 몸통 방향. 속싸개 위로도 윤곽이 보인다 |

손목·무릎·발목은 속싸개와 이불에 가려 학습에 혼란만 주므로 제외한다.

### 3-2. 키포인트로 자세를 판정하는 방법

YOLO가 낸 키포인트에서 아래 특징을 계산해 작은 분류기(MLP, 파라미터 수천 개 수준)에 넣는다.

- 코·눈 키포인트의 **신뢰도** (엎드리면 낮아진다)
- 두 눈, 두 어깨가 **함께 보이는지** (옆으로 누우면 한쪽만 보인다)
- 머리 중심과 어깨 중심을 잇는 **방향과 길이**
- 아기 검출 박스의 **가로세로 비율**

모든 키포인트 신뢰도가 낮거나 아기가 검출되지 않으면 **"확인 필요"**로 판정하고, 엎드림으로 단정하지 않는다.

## 4. 학습 데이터 계획

### 4-1. 데이터 출처

| 출처 | 용도 | 주의할 점 |
|---|---|---|
| COCO 사전학습 가중치 | 시작점 (전이학습) | 성인 위주라 그대로 쓰면 아기에게 맞지 않는다 |
| 공개 영아 자세 데이터셋 (예: SyRIP, 합성+실제 영아 자세 데이터) | 아기 체형에 적응 | 라이선스와 연구 목적 사용 조건 확인 필요. 대부분 컬러 영상이라 흑백 변환·IR 노이즈 증강 필요 |
| 침대 위 누운 자세 데이터셋 (예: SLP, 이불 덮은 조건 포함) | 이불 가림 상황 보완 | 성인 데이터이고 열화상(LWIR)은 맘캠의 근적외선(NIR)과 다르다. 보조로만 사용 |
| **자체 수집 (동의받은 가정)** | 실제 맘캠 환경 (밤 IR, 수유등, 창살) | 보호자 서면 동의, 얼굴 비식별화, 기기 밖 반출 최소화 |
| **영아 인형(모형) 촬영** | 엎드림 데이터 보충 | 아래 4-2 참고 |

### 4-2. 엎드림 데이터를 얻는 방법 (안전 원칙)

**데이터를 얻으려고 실제 아기를 엎드려 놓아서는 안 된다.** 엎드림 데이터는 다음 방법으로만 확보한다.

1. 실제 크기의 **영아 인형(마네킹)**을 다양한 침구·조명에서 촬영
2. 보호자가 지켜보는 상태에서 아기가 **스스로 뒤집은 장면**이 자연스럽게 찍힌 경우만, 동의를 받아 사용
3. 합성 데이터(3D 아기 모델 렌더링)로 보충

### 4-3. 목표 데이터 양과 라벨링

| 자세 클래스 | 목표 이미지 수 | 비고 |
|---|---:|---|
| 바로 누움 | 6,000 | 가장 흔한 자세 |
| 옆으로 누움 | 3,000 | 엎드림과 헷갈리는 경계 사례를 충분히 포함 |
| 엎드림 | 3,000 | 인형·합성 데이터로 보충, 오버샘플링 |
| 확인 필요 (심한 가림, 빈 침대, 보호자 개입) | 2,000 | 엎드림으로 오판하지 않도록 학습 |

라벨링은 이미지마다 다음을 단다.

- 아기 **검출 박스** 1개
- **키포인트 7개**: 좌표와 보임 여부 (0: 없음, 1: 가려짐, 2: 보임)
- **자세 클래스** 1개
- **촬영 조건 태그**: 낮/밤, 이불 유무, 시트 무늬, 수유등 유무 (6장 조건별 검증에 사용)

### 4-4. 데이터 분할

같은 집의 영상이 학습과 검증에 함께 들어가면, 모델이 그 집의 침대 모양을 외워서 성능이 부풀려진다. 그래서 프레임이 아니라 **가정(집) 단위**로 나눈다.

| 구분 | 비율 | 용도 |
|---|---:|---|
| 학습 (train) | 70% | 모델 학습 |
| 검증 (val) | 15% | 하이퍼파라미터 조정, 조기 종료 |
| 시험 (test) | 15% | 최종 성능 측정. 학습 중에는 한 번도 보지 않는다 |

## 5. 학습 방법

### 5-1. 단계별 학습

| 단계 | 내용 | 설정 |
|---|---|---|
| ① 전이학습 준비 | COCO 사전학습 YOLO26n-pose 불러오기, 키포인트를 7개로 재정의 | `kpt_shape: [7, 3]` |
| ② 머리 부분 먼저 학습 | 백본(특징 추출부)을 고정하고 검출·키포인트 헤드만 학습 | `freeze=10`, 30 epoch |
| ③ 전체 미세조정 | 고정을 풀고 전체를 작은 학습률로 학습 | 100 epoch, 조기 종료 `patience=20` |
| ④ 자세 분류기 학습 | ③의 키포인트 출력으로 MLP 학습 | 엎드림 클래스 가중치 높임 (Focal loss) |
| ⑤ 양자화 인식 미세조정 | INT8 변환 시 정확도 손실을 줄이기 위해 짧게 재학습 | 10 epoch |

### 5-2. 주요 하이퍼파라미터 (초기값)

| 항목 | 값 | 이유 |
|---|---|---|
| 입력 크기 | 학습 256 (정사각 레터박스), 추론 256×192 | 전처리 출력과 같은 크기. 두 값 모두 32의 배수라 YOLO에 그대로 넣을 수 있다 |
| 입력 형태 | 흑백 1채널을 3채널로 복제 | 사전학습 가중치가 3채널 입력이라 구조를 바꾸지 않는다 |
| 배치 크기 | 32 | 일반 GPU 1장 기준 |
| 옵티마이저 | Ultralytics 기본값(`optimizer=auto`) | YOLO26 기본 설정을 먼저 쓰고, 필요하면 조정 |
| 색상 증강 | `hsv_h=0, hsv_s=0`, `hsv_v=0.4` | 흑백 입력이라 색상·채도 증강은 의미 없다. 밝기만 바꾼다 |
| 좌우 반전 | `fliplr=0.5` + `flip_idx` 지정 | 반전 시 왼눈↔오른눈처럼 좌우 키포인트를 바꿔야 한다 |
| 회전·원근 | `degrees=15`, `perspective=0.0005` | 카메라 설치 각도 차이 대응 |
| 모자이크 | `mosaic=0.5`, 마지막 15 epoch는 끔 | 아기가 크게 나오는 실제 화면과 달라서 후반에는 끈다 |

### 5-3. 맘캠 환경 맞춤 증강 (전처리 문서와 연결)

Ultralytics 기본 증강 외에 다음을 추가한다.

- **IR 노이즈:** 가우시안 σ 3~12 + 샷 노이즈 (밤 화면 재현)
- **가림:** 이불 모양 다각형, 인형 모양 패치 (얼굴 가림 오탐 대응)
- **창살:** 세로 줄무늬 오버레이 (창살 침대 대응)
- **압축:** JPEG 품질 30~90 (영상 압축 손상 대응)
- **저대비:** 감마 0.6~1.6 (수유등 밝기 변화)

### 5-4. 학습 코드 예시

```yaml
# data/momcam_pose.yaml
path: datasets/momcam
train: images/train
val: images/val
test: images/test
kpt_shape: [7, 3]                 # 키포인트 7개 × (x, y, 보임 여부)
flip_idx: [0, 2, 1, 4, 3, 6, 5]   # 좌우 반전 시 바꿀 키포인트 순서
names:
  0: infant
```

```python
from ultralytics import YOLO

# ② 백본 고정 학습
model = YOLO("yolo26n-pose.pt")              # COCO 사전학습 가중치
model.train(data="data/momcam_pose.yaml", imgsz=256,
            epochs=30, batch=32, freeze=10,
            hsv_h=0, hsv_s=0, hsv_v=0.4, fliplr=0.5,
            degrees=15, mosaic=0.5, project="runs", name="stage1")

# ③ 전체 미세조정
model = YOLO("runs/stage1/weights/best.pt")
model.train(data="data/momcam_pose.yaml", imgsz=256,
            epochs=100, patience=20, batch=32, close_mosaic=15,
            project="runs", name="stage2")

# 시험셋 검증
metrics = model.val(data="data/momcam_pose.yaml", split="test")
print(metrics.box.map50, metrics.pose.map)    # 검출 mAP50, 키포인트 mAP50-95

# 기기용 INT8 모델로 내보내기 (LiteRT/TFLite, 보정용 데이터로 val 이미지 사용)
model.export(format="tflite", imgsz=256, int8=True, data="data/momcam_pose.yaml")
```

## 6. 검증 방법

검증은 **세 단계**로 나눈다. 모델 점수가 높아도 실제 경보가 늦거나 자주 틀리면 쓸 수 없기 때문이다.

### 6-1. 1단계: 모델 성능 (시험셋 이미지 단위)

| 지표 | 의미 | 목표 | 결과 |
|---|---|---|---|
| 아기 검출 mAP50 | 아기를 제대로 찾는 정도 | 0.95 이상 | 측정 예정 |
| 키포인트 mAP-pose 50-95 | 관절 위치가 얼마나 정확한지 (OKS 기준) | 0.60 이상 | 측정 예정 |
| 엎드림 재현율 (Recall) | 실제 엎드림 중 놓치지 않은 비율 | **0.95 이상** | 측정 예정 |
| 엎드림 정밀도 (Precision) | 엎드림이라 한 것 중 실제 엎드림 비율 | 0.85 이상 | 측정 예정 |
| 혼동 행렬 | 옆으로 ↔ 엎드림 혼동이 얼마나 되는지 | 확인용 | 측정 예정 |

**재현율을 정밀도보다 우선한다.** 엎드림을 놓치는 것(미탐)이 잘못 울리는 것(오탐)보다 위험하기 때문이다. 대신 오탐은 2단계의 5초 지속 판정으로 줄인다.

### 6-2. 조건별 성능 (약점 찾기)

전체 평균만 보면 밤이나 이불 덮은 상황의 약점이 묻힌다. 촬영 조건 태그별로 나눠서 따로 측정한다.

| 조건 | 엎드림 재현율 | 비고 |
|---|---|---|
| 낮 / 컬러 | 측정 예정 | |
| 밤 / IR | 측정 예정 | 가장 중요. 전체보다 5%p 이상 낮으면 IR 데이터 추가 |
| 얇은 이불 덮음 | 측정 예정 | |
| 잔무늬 시트 | 측정 예정 | |
| 창살 가림 | 측정 예정 | |
| 속싸개 착용 | 측정 예정 | |

### 6-3. 비교 실험 (설계가 맞는지 확인)

| 실험 | 비교 대상 | 확인할 점 |
|---|---|---|
| 모델 크기 | YOLO26n-pose vs YOLO26s-pose | s가 n보다 엎드림 재현율이 크게 높지 않다면 n 유지 |
| 판정 방식 | pose + MLP vs YOLO26n-cls | 정확도가 비슷하면 이유를 설명할 수 있는 pose 방식 유지 |
| 전처리 효과 | CLAHE·노이즈 제거 있음 vs 없음 | 밤 IR 조건 성능 차이로 전처리 효과 확인 |
| 증강 효과 | 맞춤 증강 있음 vs 없음 | 이불·창살 조건 성능 차이 확인 |
| 양자화 손실 | FP32 vs INT8 | 엎드림 재현율 하락이 1%p 이내여야 함 |

### 6-4. 2단계: 이벤트 성능 (영상 단위)

실제로는 프레임 하나가 아니라 **"엎드림이 5초 이어졌을 때 경보가 울렸는가"**가 중요하다. 시험셋 영상 전체를 `code/momcam_preprocess.py`의 판정 로직(EMA 평활 + 5초 중 4초 + 히스테리시스)에 통과시켜 측정한다.

| 지표 | 목표 (PRD) | 결과 |
|---|---|---|
| 엎드림 이벤트 감지율 | 95% 이상 | 측정 예정 |
| 엎드림 시작 → 경보까지 시간 | 5초 이내 (95% 이상의 경우) | 측정 예정 |
| 오탐 경보 횟수 | 카메라 1대당 하루 1회 이하 | 측정 예정 |
| "확인 필요" 발생 비율 | 하룻밤 수면 시간의 5% 이하 | 측정 예정 |

### 6-5. 3단계: 기기 실측 (실제 하드웨어)

| 항목 | 방법 | 목표 | 결과 |
|---|---|---|---|
| 프레임당 처리 시간 | 전처리 + YOLO + 판정까지 기기에서 측정 | 200ms 이하 (5fps) | 측정 예정 |
| 모델 용량 | INT8 영상 모델 + 오디오 모델 합계 | 15MB 이하 | 측정 예정 |
| Wi-Fi 차단 시 경보 | 공유기를 끈 상태에서 인형을 엎드려 놓기 | 99.9% 이상 경보 | 측정 예정 |
| 밤샘 연속 동작 | 8시간 연속 실행, 메모리·온도 기록 | 오류·재시작 0회 | 측정 예정 |
| 실제 가정 시범 사용 | 동의받은 가정 5곳, 2주 | 보호자 체감 오탐 하루 1회 이하 | 측정 예정 |

## 7. 한계와 위험

1. **아기 데이터 부족:** 공개 영아 데이터가 적고 대부분 컬러 영상이다. 밤 IR 성능은 자체 수집 데이터 양에 크게 좌우된다.
2. **엎드림 데이터의 현실성:** 인형과 합성 데이터는 실제 아기의 움직임·체형과 차이가 있다. 시범 사용 단계에서 반드시 다시 확인해야 한다.
3. **가림에 대한 근본적 한계:** 이불이 얼굴을 완전히 덮으면 어떤 카메라 모델도 자세를 알 수 없다. 이 경우 "확인 필요"로 알리는 것이 최선이다.
4. **의료기기가 아님:** 맘캠은 보호자를 돕는 보조 모니터링 기기다. 이 모델의 판정은 아기의 안전을 보장하지 않으며, 보호자의 직접 확인을 대신할 수 없다.
