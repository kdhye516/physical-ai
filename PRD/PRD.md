# PRD: 맘캠 — 아기 울음·뒤척임 감지 홈카메라

- **제품명:** 맘캠
- **주요 입력 데이터:** 카메라 영상, 마이크 음성, 기기 상태 및 네트워크 상태
- **주요 출력(행동):** 아기 울음·엎드림 의심 감지, 기기 경보음, 부모 스마트폰 알림

> **안전 범위:** 맘캠은 보호자가 아기를 살피도록 돕는 보조 모니터링 기기다. 의료기기나 영아 돌연사 예방 장치로 설계·홍보하지 않는다. 감지 결과만으로 아기의 상태가 안전하다고 판단해서는 안 된다.

## 1. 문제 정의 (Problem Statement)

부모는 아기가 자는 동안에도 울음이나 수면 자세 변화를 확인해야 한다. 기존 홈카메라는 영상을 직접 계속 보거나 소리 알림에 의존하는 경우가 많아, 보호자가 화면을 주시하지 않으면 이상 상황을 놓치거나 잦은 오탐 알림으로 피로해질 수 있다.

맘캠은 카메라 영상과 음성에서 울음 및 엎드림 의심 상황을 분석해 보호자에게 알린다. 자세 감지는 아기의 얼굴이 보이지 않는 상황이나 이불·장난감에 가려진 상황에서 정확도가 떨어질 수 있으므로, 결과를 확정적인 안전 판정으로 제공하지 않고 보호자가 직접 확인하도록 안내한다.

AI는 영상의 자세와 음성의 울음 특성을 함께 분석해 단순 움직임이나 주변 소음으로 인한 오탐을 줄이는 데 사용한다. **분석의 기본 처리는 기기 안에서 수행**해 영상·음성을 상시 클라우드로 전송하지 않도록 한다.

## 2. 사용자 시나리오 (User Scenario)

1. **설치:** 보호자가 침대 전체가 보이는 위치에 맘캠을 설치하고 앱에서 카메라를 Wi-Fi에 연결한다. 사생활 보호 구역과 알림 받을 보호자 기기를 설정한다.
2. **데이터 수집:** 카메라는 영상과 음성을 입력받는다. 영상·음성은 기본적으로 기기 내 분석에 사용하며, 상시 녹화·클라우드 저장은 기본 기능에 포함하지 않는다.
3. **AI 분석:** 저전력 기기에서 자세 인식 모델과 울음소리 분류 모델을 실행한다. 프레임 간 움직임과 소리 패턴을 함께 살펴 일시적인 뒤척임이나 TV 소리 등의 오탐을 줄인다.
4. **판단 생성:** 울음 또는 엎드림 의심 이벤트가 기준 시간 이상 지속되면 이벤트를 생성한다. 가림·저조도 등으로 판단이 어려운 경우에는 “확인 필요” 상태로 처리한다.
5. **행동:** 엎드림 의심 이벤트는 기기 경보음을 울리고, Wi-Fi 연결 시 보호자 앱에 푸시 알림을 보낸다. 울음 이벤트는 보호자가 설정한 알림 정책에 따라 알림을 보낸다. 네트워크가 끊기면 앱 알림은 보류되지만 기기 경보는 독립적으로 동작한다.
6. **확인 및 후속 행동:** 보호자는 알림을 열어 카메라의 현재 화면을 확인하고 직접 아기 상태를 살핀다. 기기는 감지 결과를 의료적 진단이나 응급 대응 지시로 표현하지 않는다.

## 3. 성공 지표 (Success Metrics)

아래 목표는 양산 전 검증을 위한 **초기 제품 목표(가정)**이며, 실제 성능은 다양한 조명·침구·설치 환경에서 시험해 확정한다.

| 지표 | 목표 |
|---|---:|
| 엎드림 의심 이벤트 감지 후 기기 경보 시작 | 5초 이내, 시험 조건 기준 95% 이상 |
| 엎드림 의심 이벤트 감지 민감도 | 시험 데이터 기준 95% 이상 |
| 오탐으로 인한 엎드림 알림 | 카메라 1대당 하루 1회 이하(가정) |
| 울음 감지 이벤트 분류 정확도 | 시험 환경 기준 F1 0.90 이상(가정) |
| 기기 자체 경보 동작률 | Wi-Fi 차단 시험에서 99.9% 이상(가정) |
| 영상·음성의 상시 클라우드 전송 | 기본 설정에서 없음 |
| 월간 기기 가동률 | 99% 이상(가정, 전원 공급 시간 기준) |
| 사용자 알림 확인률 | 앱 알림 전달 성공률 99% 이상(네트워크 정상 조건) |

감지 성능은 아기 월령, 카메라 각도, 침구, 조도, 주변 소음에 따라 달라질 수 있다. 출시 전에는 실제 사용 환경을 대표하는 별도 검증이 필요하다.

| 구성 | 사용 기술 | 선정 이유 |

| 센서 | 마이크, 조도 센서, 온도 센서(선택) | 울음 분석, 저조도 판단, 환경 상태 표시 |

| 데이터베이스 | 기기 설정 및 이벤트 메타데이터용 PostgreSQL 또는 관리형 DB | 영상 없이 이벤트 시간·종류·기기 상태를 최소한으로 저장 |
| 대시보드 | 운영·기기 상태 확인용 웹 대시보드(내부용) | 연결 상태, 펌웨어 버전, 장애율 확인 |
| 알림 시스템 | 모바일 푸시 알림 서비스(APNs/FCM), 기기 부저 | 보호자 앱 알림과 Wi-Fi 단절 시 기기 자체 경보 |
| 보안 | Secure Boot, 서명된 OTA 업데이트, 기기별 인증서, 저장 데이터 암호화 | 가정 내 카메라 기기의 무단 접근 및 변조 위험 완화 |

## 5. 개발 범위 / 비범위 (Scope)

### 개발 범위 (In Scope)

- 1080p 카메라 기반 실시간 영상 입력 및 야간 모드
- 기기 내 울음소리 감지와 자세 변화 분석
- 엎드림 의심 이벤트 발생 시 5초 이내 기기 경보 목표
- Wi-Fi 연결 시 보호자 앱으로 이벤트 푸시 알림
- Wi-Fi가 끊겨도 동작하는 기기 자체 경보
- 영상·음성의 기본적인 상시 클라우드 전송 차단
- 이벤트 종류·발생 시각·기기 상태 기록
- 카메라 가림, 저조도, 네트워크 단절 등 기기 상태 알림
- 펌웨어 보안 업데이트와 버전 관리
- 감지 결과를 보호자가 직접 확인하도록 하는 앱 화면

### 개발 제외 범위 (Out of Scope)

- 아기의 건강 상태 진단 및 의료기기 기능
- 영아 돌연사 예방 또는 사고 방지 보장
- 보호자 확인 없이 아기에게 직접 접촉하거나 환경을 변경하는 자동 행동
- 기본 서비스의 24시간 클라우드 영상 저장·분석
- 얼굴 인식이나 아기 신원 식별
- 영상만으로 수면 안전을 확정 판정하는 기능
- 응급기관 자동 신고 기능
- 스마트 침대·가습기 등 타사 기기를 자동 제어하는 기능
- 월 구독료가 필요한 유료 영상 저장 서비스

## 6. ROI 분석 (Business Value)

**산정 기준(가정):** 판매 목표 10만 대가 모두 판매된 시점의 회사 관점 비용·편익을 단순 계산한다. 소비자 판매가 9만 원은 매출이며, 회사의 원가·마진 자료가 없으므로 ROI 산식에는 포함하지 않는다. 월 절감액은 클라우드 분석·저장 비용을 회피하는 효과로 가정한다.

| 항목 | 산정 근거 | 금액 |
|---|---|---:|
| 초기 투자비 (CAPEX) | AI 칩 추가비 0.6만 원 × 10만 대 + 모델·펌웨어 개발 및 검증비(가정) 3억 원 | **9억 원** |
| 월 절감액 (Gross Benefit) | 클라우드 영상 분석비 1,500원 × 10만 대/월 + 영상 저장·보안비 연 1억 원 ÷ 12 | **약 1억 5,833만 원/월** |
| 월 운영비 (OPEX) | 서버·푸시·기기 관리 월 2,000만 원 + 유지보수·모델 개선 월 3,000만 원(가정) | **5,000만 원/월** |
| 월 순 절감액 (Net Benefit) | 월 절감액 − 월 운영비 | **약 1억 833만 원/월** |
| 연간 순 절감액 | 월 순 절감액 × 12 | **약 13억 원/년** |
| 연간 ROI | 연간 순 절감액 ÷ 초기 투자비 × 100 | **약 144%** |
| 투자 회수기간 | 초기 투자비 ÷ 월 순 절감액 | **약 0.83개월** |

**최종 판정:** 제시된 클라우드 비용 가정이 실제 운영에서도 유지되고 10만 대가 판매·활성화된다면, 엣지 분석은 영상 전송·저장 비용을 줄이는 데 경제성이 있다. 다만 개발비·기기 인증·고객지원·유통 비용과 판매 속도에 따라 회수기간은 크게 달라지므로, 위 수치는 사업성 검토용 가정치다. 아기 자세 감지는 안전과 직결될 수 있으므로 비용 절감보다 검증된 감지 성능과 오탐·미탐 관리, 사용자에게 한계를 정확히 알리는 설계를 우선해야 한다.
